# Free POC deployment: APK for a client

**What gets set up:** the API on **Render** (free), login and database on **Firebase** (free Spark plan), and the APK built by **Expo EAS** (free). No credit card is needed for any of them. AstrologyAPI credits are used as usual.

**Know before you start:**

- **The free server sleeps.** After about 15 minutes without use, Render's free server goes to sleep. The next request then takes 30–60 seconds while it wakes up.
- **App Check is off in this demo mode.** Logins are still required, and the daily per-user limit (30 provider calls) still applies. Turn App Check on before any real launch.
- **Never paste secrets into chat, email or this repository.** That means the Firebase key file and the AstrologyAPI key. They go into Render's dashboard only.

---

## Part A: Accounts

1. **GitHub (push the code).** Render deploys from GitHub. Sign in through the browser, which grants the permissions git needs:

   ```powershell
   winget install GitHub.cli
   gh auth login        # GitHub.com → HTTPS → Login with a web browser
   cd D:\astrology
   git push -u origin main
   ```

2. **Firebase:** sign in at https://console.firebase.google.com with your Google account.
3. **Render:** go to https://render.com and choose **Sign up with GitHub**.
4. **Expo:** go to https://expo.dev and **Sign up**.

## Part B: Firebase project

1. Click **Add project**, name it (for example `astro-poc`), and turn Google Analytics off. Note the **project ID** it shows (for example `astro-poc` or `astro-poc-1a2b3`).
2. Go to **Build → Authentication → Get started → Sign-in method → Email/Password → Enable → Save**.
3. Go to **Build → Firestore Database → Create database**:
   - location: **asia-south1 (Mumbai)**;
   - mode: **Start in production mode**.
4. Go to **Project settings** (gear icon) **→ General → Your apps → Web (`</>`)**. Give it a nickname and click **Register app**. Keep the `firebaseConfig` values open; you need `apiKey`, `authDomain`, `projectId` and `appId` in Part D. They are public identifiers, not secrets.
5. Go to **Project settings → Service accounts → Generate new private key**. A JSON file downloads.
   - ⚠️ **This file is a secret:** it gives full access to the database.
   - Leave it in `Downloads`. Do not move it into the project folder; git and Docker ignore it anyway, as a safety net.
6. Apply the database rules (the app only talks to Firestore through the API). Replace `astro-poc` with your project ID:

   ```powershell
   cd D:\astrology
   npx firebase-tools login
   npx firebase-tools deploy --only firestore:rules,firestore:indexes --project astro-poc --config infra/firebase/firebase.json
   ```

## Part C: API server on Render

1. In the Render dashboard, choose **New → Blueprint**, connect GitHub, pick **astro_app**, and click **Apply**. Render reads `render.yaml` and creates a service called `astro-api`.
2. Render asks for three values; type them in:
   - `FIREBASE_PROJECT_ID`: your project ID from Part B.
   - `ASTROLOGYAPI_USER_ID`: the same value as in your local `.env`.
   - `ASTROLOGYAPI_API_KEY`: the same value as in your local `.env`.

   `UID_HASH_PEPPER` is generated by Render automatically.

3. Add the Firebase key file:
   1. Open the **astro-api** service and go to **Environment → Secret Files → Add Secret File**.
   2. Set **Filename** to `firebase-key.json`.
   3. Set **Contents**: open the downloaded JSON file in Notepad, select all, copy and paste.
   4. Click **Save**, then **Manual Deploy → Deploy latest commit**.
4. Wait for **Live**; the first build takes about 5–10 minutes. Copy the service URL, for example `https://astro-api-xxxx.onrender.com`.
5. Check it in a browser:
   - `https://…onrender.com/healthz` should show `{"status":"ok"}`;
   - `https://…onrender.com/v1/me` should show an error with code `UNAUTHENTICATED`. That is correct: it means login is required.

**If the deploy fails:** open **Logs**. A line starting `Invalid configuration:` names the missing setting. Fix it under **Environment** and deploy again.

## Part D: Build the APK

1. Fill in `apps/mobile/eas.json` under `build → preview → env`:
   - `EXPO_PUBLIC_API_URL`: your Render URL (starts with `https://`, no `/` at the end).
   - The four `EXPO_PUBLIC_FIREBASE_*` values from Part B step 4.
2. Install the build tool once and sign in:

   ```powershell
   npm install -g eas-cli
   eas login
   ```

3. Build:

   ```powershell
   cd D:\astrology
   npm run build:apk
   ```

   - The command refuses to start while any value in `eas.json` is still a placeholder.
   - On the first run, answer **Yes** to "Create an EAS project", and **Yes** to "Generate a new Android Keystore". Expo keeps the keystore for you; it signs every future update.
   - Free builds can wait in a queue (often 10–30 minutes). The terminal shows a link where you can follow the build.

4. When it finishes, you get a link to the **.apk**. Open it on your Android phone and test:
   1. create an account;
   2. accept consent;
   3. add a profile;
   4. open the chart.

## Part E: Send it to the client

1. Send the APK link from Expo, or download the `.apk` and share it through Google Drive or WhatsApp.
2. On their phone, open the file. When asked, allow **Install unknown apps** for that app (Chrome, Files or WhatsApp), then tap **Install**.
3. Tell them:
   - sign up with email and password;
   - the first open after a quiet period can take up to a minute;
   - it is Android only (iPhone needs a paid Apple Developer account).

## Updating later

- **API changes:** commit and `git push`. Render redeploys automatically.
- **App changes:** run `npm run build:apk` again and send the new link. The app installs over the old one, because it is signed with the same keystore.
